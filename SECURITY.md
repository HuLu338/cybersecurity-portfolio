# Testing and publication boundaries

Course testing described here concerns owned or controlled lab virtual machines. The deliberately vulnerable target belongs on the isolated VMware LAN Segment, not a public or bridged network. Existing software projects are local educational prototypes with separate source-based case studies.

The published addresses `192.168.77.10` and `192.168.77.20` identify private lab guests. They are not public targets. A service banner does not establish exploitability. Follow-up recommendations are labelled as recommendations rather than completed tests.

## Public evidence

- No virtual disks, private coursework PDFs, resumes, credentials, personal contact numbers or home addresses are included.
- Selected screenshots show lab output without repainting results. Full VMware screenshots with host-specific details are kept outside the public repository.
- Project evidence notes distinguish learner-supplied captures from assistant-operated captures and retain the recorded dates.
- GitHub account authentication and other local settings are never stored in this repository.
- New software case studies link to public repository snapshots and distinguish inspected assertions from newly executed tests. The Web Vuln Lab policy illustration runs only a small explanatory UI on its project page; it does not call a lab API.
- The home page stage repeats that case as a scroll-driven diagram. It is drawn from the same policy description and test assertions; it sends no request, executes no code and shows no live result.
- Known prototype limits are stated in each case study, including simulated identity, administrative API-key use and further deployment hardening. Private repositories and upstream forks are not represented as original public projects.
