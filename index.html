05 / LEARNING

What the course is teaching me.

The two course activities that gave me the clearest starting point were building an isolated virtual lab and reading an Nmap service scan. They connect basic networking with security work. The lab asks whether the test environment is safely configured. The scan asks what is exposed inside that environment. Keeping these questions separate helps me explain what each result supports, instead of treating a tool's output as a complete security assessment.

For the virtual lab, I worked with Kali Linux and Metasploitable 2 on a private VMware LAN Segment. The important lesson was to check both settings and guest output. A successful ping shows that two chosen addresses can communicate, but it does not prove isolation from every other network. Adapter types, active interfaces and routing tables provide further evidence. I also learned to keep the guest clock readings separate from the date when evidence was collected.

The Nmap exercise made service interpretation more concrete. The recorded refresh run checked 1,000 common TCP ports and found 23 open and 977 closed in 11.55 seconds. I need to distinguish those observations from a confirmed vulnerability. For example, the light probe reported rpcbind on 2049, while the tentative product label on 513 did not include an exact version. These limits belong in the explanation. I confirmed personal reproduction and understanding earlier; the later assistant-operated refresh is labelled in the project evidence.

One documented problem was command compatibility. The old target did not accept ip -br addr and returned an unknown-option message. Using ifconfig -a and route -n provided the address and routing information that was needed. The recorded error helped separate a command-version problem from an interface or connection failure. For future work, I would check the available command options before repeating a command from a newer Linux environment. This troubleshooting account is based on the retained console record, not an invented debugging session.

I still find it difficult to understand how to defend systems when attackers use AI models. I do not yet have a tested defence for that situation. Before making strong claims about advanced attacks, I need a stronger base in networking, operating systems, web requests and evidence analysis. I also need to explain what a proposed control is meant to stop and show whether it works in a controlled test.

My goal is to strengthen these foundations by February 2027 through projects published on GitHub. A concrete target is to publish or improve one owned web/API project with two issue, repair and retest cases. I will provide setup instructions, repeatable checks and both allowed and denied test cases. I want another learner to be able to follow the steps and comment on the results. I will also track stars as a sign of interest, but judge technical progress using reproducibility, tests and review feedback. These measures make the goal more useful than popularity alone.
